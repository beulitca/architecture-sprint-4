# Архитектурное решение по трейсингу

## Мотивация
Трейсинг позволит повысить уровень обслуживания клиентов и остановить их потерю. 
- клиент не будет вовлечен в процесс поиска ошибки, сразу будет получать результат исправления
- причина ошибки будет устанавливаться в короткие сроки, а также быстро выявляться меры по ее решению в рамках поддержки
- трейсинг позволит приоретизировать устранение слабых мест системы
- улучшение sla поддержки

## Системы и процессы, подлежащие трейсингу
0. Shop API -> Shop DB, s3 storage - регистрация заказов от юрлиц, для контроля времени поступления заказа в систему
- trace_id - идентификатор операции
- span_id = 1 - идентификатор ступени обработки
- id заказа
- время поступления заказа
- пользователь
- статус заказа
- количество полигонов 3d-модели (для отслеживания зависимости обработки от сложности расчетов)
1. CRM-API -> RMQ -> MES-API - запросы по расчету стоимости
- trace_id - идентификатор операции
- span_id = 2 - идентификатор ступени обработки
- время обработки заказа
- пользователь
- статус заказа
- количество полигонов 3d-модели (для отслеживания зависимости обработки от сложности расчетов)
2. MES-API -> RMQ -> CRM-API - ответы по расчету стоимости
- trace_id - идентификатор операции
- span_id = 3 - идентификатор ступени обработки
- id заказа
- время обработки заказа
- пользователь
- статус заказа
- количество полигонов 3d-модели (для отслеживания зависимости обработки от сложности расчетов)
3. CRM-API -> RMQ -> MES-API - сообщения о подтверждении заказа менеджером по подажам
- trace_id - идентификатор операции
- span_id = 4 - идентификатор ступени обработки
- id заказа
- время обработки заказа
- пользователь
- менеджер по продажам
- статус заказа
4. MES-API -> RMQ -> CRM-API - сообщения об изменении статуса заказа
- trace_id - идентификатор операции
- span_id = 5 - идентификатор ступени обработки
- id заказа
- время обработки заказа
- пользователь
- статус заказа
- оператор
5. MES-API -> RMQ -> CRM-API - регистрация заказов юрлиц
- trace_id - идентификатор операции
- span_id = 1 - идентификатор ступени обработки
- id заказа 
- время поступления заказа
- юрлицо
- статус заказа
- количество полигонов 3d-модели (для отслеживания зависимости обработки от сложности расчетов)
6. + flow получения уведомления от транспортной компании (в условиях не описана реалиация)
- trace_id - идентификатор операции
- span_id = 1 - идентификатор ступени обработки
- id заказа 
- время поступления уведомления 
- менеджер по продажам в случае ручного закрытия заказа

## Улучшение метрик
1. Снижение Number of simultanious sessions for MES API, Number of requests (RPS) per user for MES API т к операторы будут получать информацию о заказах с первого раза
2. Повышение Number of requests (RPS) for internet shop API, в связи с ростом числа постоянных клиентов и качества сервиса
3. Снижение числа ошибок 
Number of HTTP 200 for shop API
Number of HTTP 200 for CRM API
Number of HTTP 200 for MES API
Number of HTTP 200 for MES API с меткой method="GET"
4. Повышение числа удачных запросов 
Number of HTTP 500 for shop API
Number of HTTP 500 for CRM API
Number of HTTP 500 for MES API
5. Снижение числа необработанных сообщений очереди и числа сообщений в обработке
Number of dead-letter-exchange letters in RabbitMQ
Number of message in flight in RabbitMQ
6. Увеличение загрузки процессора из-за трейсинга систем
CPU % for shop API
CPU % for MES API
CPU % for CRM API

## Компромисы
Необходимость найма сотрудников поддержки для разбора ошибок, дополнительная нагрузка на DevOps инженера по постоянной поддержке мониторингового сервера. Затраты на оборудование. Риск дополнительной загрузки 

Если MES написан на C# версии ниже 4, то могут быть проблемы с использованием sdk OpenT. Вероятно, раз MES уже крутится в облаке, вероятнее всего, под Linux, то это уже C# Core и выше, и проблем быть не должно. 

Дополнительная нагрузка на CPU сервера при настройке трейсинга, создает определенные риски для системы, узлы которой не реплецируются и, вероятно, уже испытывают перегрузки. 

## Меры безопасности 
Авторизация сотрудника для просмотра логов. Маскирование ПД, чтобы невозможно было деанонимизировать состоятельных клиентов. Во вне отладочную информацию предоставлять не планируется.
