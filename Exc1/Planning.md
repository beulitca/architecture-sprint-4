#Планирование: анализ, идентификация проблем и поиск решений

## Существующие проблемные места:

1. Розничные (пользователи сайта) и корпоративные (пользователи API MES) клиенты не получает сообщение о готовности заказа
2. Операторы - исполнители не могут оперативно получать данные о новых заказах на сайте MES
3. Отсутствие мониторинга и логирования системы, что препятствует оперативному траблшутингу проблем
4. Вероятно, низкая производительность узла BD MES, о чем свидетельствет проблема с просмотром списка заказов
5. Недостаточная скорость поставки релизов с исправлениями при высокой скорости роста бизнеса
6. Недостаточная декомпозиция система по бизнес-функциям, что ухудшает производительность и возможность обновлений (расчет стоимости совмещен с функционалом работы с операторами и приемкой заказов от юрлиц)


## Потенциальные проблемные места:

1. Отсутствие возможностей масштабирования системы, реализация к этому не подготовлена, превышение нагрузки на любом узле
2. Проблемы с развитием функционала из-за п 6.
3. Низкая скорость обновления
4. Проблемы с поддержкой системы в работоспособном состоянии из-за непрозрачности ее работы - отсутствия мониторинга, логов и трейсов

## Инициативы по разрешению ситуации
1. Повысить прозрачность работы системы
1.1 Настроить мониторинг и уведомления для выявления слабых мест и формирования плана устранения критичных сбоев
1.2 Настроить трэйсинг на узлах MES, для выявления проблем с обработкой заказа
1.3 Настроить логирование для узлов магазина, для выявления проблем с точки зрения клиента
2. Взять сотрудника поддержки для реагирования на алерты и ручного разрешения конфликтов с клиентами на первое время
3. Снизить нагрузку на критичные узлы 
3.1 Убедиться, что настроен паттерн back pressure в RMQ
3.2 Внедрить кеширование и тем самым снизить нагрузку на критичные элементы
4. Подготовиться к глобальной переработке системы на микросервисную архитектуру 
4.1 Автоматизировать процессы деплоя
4.2 Автоматизировать процессы тестирования
5. Декомпозировать систему по бизнесфункциям к паттерну микросервисной архитектуры
9. Применить вертикальное масштабирование, где необходимо
10. Перейти к развитию функциональности и наращиванию числа потребителей

За полгода надо обеспечить корректную работу и предотвратит потерю клиентов, поэтому 
необходимо выполнить первые 3 пункта со всеми включенными шагами. 

Архитектура через полгода должна соответствовать описанной в последующих заданиях. 
Далее имеет смысл произвести декомпозицию сервиса MES на модуль расчета стоимости, модуль выполнения заказа, 
реализовать узел управления заказами как розничных так и корпоративных клиентов, выделить отдельно бек-и пользовательских порталов crm, магазина, производителей. Применить паттерны проектирования микросервисной архитектуры, в т ч data base for service.
