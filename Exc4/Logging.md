# Архитектурное решение по логированию

## Мотивация
Логирование позволит повысить уровень обслуживания клиентов и остановить их потерю. 
- клиент не будет вовлечен в процесс поиска ошибки, сразу будет получать результат исправления
- причина ошибки будет устанавливаться в короткие сроки, а также быстро выявляться меры по ее решению в рамках поддержки
- улучшение sla поддержки

Логировать будем данные CRM API, т к сервис управляет сменой статуса заказа и получает данные о заказе из разных узлов.
Срез заказа в любом статусе избавит от необходимости получать данные от клиента и предоставит максимум информации для отладки.
Также CRM написан на Java Spring внутри компании, у нас есть ресурс двух разработчиков на этой технологии, которые владеют кодом и смогут внедрить логи.

## Системы и процессы, подлежащие логированию
В первую очередь я бы ввела логирование в модуле CRM API как мастер-системе по обработке заказаов, через которую проходят все статусы выполнения заказа. Отслеживание статусов заказа, в которых возникает максимальное количество проблем уже в большой степени позволит локализовать этап появления проблемы.

Вероятнее всего ошибки возникают в перегруженном узле MES, но настройка логирования для этого узла нежелательна по текущем этапе по причинам:
- в данный момент для траблшутинга хватает опроса пользователей, т е данных уровня CRM API, в то время как MES реализует сложную внутреннюю логику
- MES перегруженный узел, логирование может усугубить нагрузку на память и cpu
- ресурсов для разработки на C# меньше, чем на JavaSpringBoot
- статусы заказов, присваиваемые в рамках MES отправляются в CRM, что позволяет установить проблемный шаг обработки на уровне crm

Если после выявления проблемного этапа обработки данных дебаггинга, трассировки и мониторинга для нахождения ошибки будет недостаточно, то зону покрытия логами можно будет расширить 

Логирование INFO:
- id Заказа
- id Пользователя
- статус заказа
- запрос на изменение статуса, полученный от транспортной компании/из RMQ/Shop API
- запрос на обработку заказа, отправленный в RMQ
- timestamp

Логирование ERROR - Позволит отследить ошибки по таймауту и ошибки в данных:
- id Заказа
- id Пользователя
- статус заказа
- объект заказа
- Код, описание ошибки
- timestamp
